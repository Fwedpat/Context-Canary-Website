Canary docs

Canary puts one small instruction at the start of a message, passes the message to Copilot, and checks whether Copilot keeps following the instruction as the chat grows. Copilot answers as normal, with all its tools. Canary only adds the instruction and keeps score.

Install

Canary isn't published to the Marketplace yet. Build a package from the source and install it locally. You need Node.js to build it, and VS Code 1.138 or later with Copilot Chat to use it.

npm install
npm run package
  1. Open the Command Palette and run Extensions: Install from VSIX….
  2. Choose context-canary-0.0.3.vsix and reload VS Code.

To work on it instead, open the project in VS Code and press F5 to start an Extension Development Host.

Using Canary

Start the canary

Type @canary and your message. You can also click the bottom-right status bar bird to open its window, the same one that appears on hover, then choose Add to Chat to put @canary in the chat box without sending anything. The top-right bird in the Chat view still starts a new Canary chat.

@canary Explain how closures work

The first time, Canary asks what it should call you. It then sends your message to Copilot as a normal message, with a short instruction added above it.

You will see that line in the chat, because that is how Copilot receives it. Its wording is fixed and isn't in the settings. It is sent only once and never repeated, so Copilot has to keep remembering it. The @canary message before it only says “Continue to prompt normally.” It doesn't describe the instruction, because in testing Copilot treated instruction-like text in an earlier reply as suspicious.

Keep chatting

Carry on with Copilot as usual. You don't need @canary again. Each reply is checked and the bird updates. Hover it to see replies checked, followed and missed, and misses in a row.

Use it in a chat you already have

Use @canary for a message in any chat. Scoring starts at that message, and earlier replies aren't judged.

Start a fresh chat

Run Canary: New Chat with Canary from the Command Palette, the Chat view's title bar, or the bird's hover. It opens a new chat and offers to add @canary, unless you turned off canary.promptOnNewChat.

Review before sending

Turn off canary.sendImmediately and Canary puts the message in the chat box instead, so you can edit it and send it yourself. Keep the line above your message as it is, or the chat won't be tracked.

How replies are read

VS Code saves every chat as a file on your computer. Canary looks in the saved chats for the current window and finds one where a Copilot message starts with your instruction. It then checks every Copilot reply from that message on. Files that don't contain your instruction are never parsed, and unchanged files aren't read again.

Replies that are still being written, were cancelled or came back empty aren't scored, so they can never count as misses. Nothing is sent anywhere, and Canary doesn't keep the text of replies.

How replies are checked

A reply must contain your name as a whole word, ignoring case, so “Fred” matches but “Frederick” doesn't. Everything Copilot said in that reply counts, including text around tool calls. A reply that matches followed the instruction. One that doesn't missed it.

Bird states

StateWhenLooks like
HealthyCopilot's last reply followed the instruction.Yellow bird
FadingThe last reply missed it.Bird on a warning background
DyingTwo replies in a row missed it (configurable).Slumped bird on an error background

A canary that follows the instruction again goes back to healthy, but the missed replies stay in the counts. The bird shows the most recently active tracked chat. You get a notification when the state gets worse.

Settings

SettingDefaultPurpose
canary.userNameemptyThe name Canary asks Copilot to use. Asked for on first use.
canary.missesBeforeDying2Misses in a row before the bird is dying, from 2 to 10.
canary.sendImmediatelytrueSend the message to Copilot straight away, or place it in the chat box for you to send.
canary.notificationstrueNotify when the canary gets worse.
canary.promptOnNewChattrueAsk before adding @canary to chats started with the Canary command.

Limits

  • Your message appears twice. First as your @canary message, then as the message Canary passes to Copilot. Canary asks VS Code to attach files and selections you referenced, and says so if another kind of attachment can't be carried over. Check that attachments arrived before relying on them.
  • It reads a saved-chat format VS Code doesn't promise to keep. If it changes, chats are reported as unreadable, never as misses.
  • The check is a text match, so a reply that includes the name without following the instruction properly still counts as followed.
  • A miss shows that one early instruction was lost. It doesn't tell you what else was. A follow doesn't prove everything is remembered.
  • It can't tell you when Copilot compacts a chat. VS Code doesn't expose that to extensions.
  • Only chats where you used @canary are tracked. Other chats are never touched.

Canary has no backend and collects no analytics. An earlier development version added a hook file to ~/.copilot/hooks. This version removes it on startup if it finds it.

Build and test

npm run test:unit   # matching, saved-chat reading, scoring and scanning
npm test            # compile, lint, and tests inside VS Code
npm run package     # build context-canary-0.0.3.vsix

npm test downloads a VS Code test build the first time it runs. The publisher in package.json is a local placeholder. Set your own and choose a license before publishing.
